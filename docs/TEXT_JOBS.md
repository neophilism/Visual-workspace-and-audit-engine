# Private text processing job inspection

`./text-jobs` projects one authorized snapshot from Processing's pinned text-job ledger. Stored job keys and revisions are preserved. Source, derivative and receipt links are exact editions, explicitly not independently read or verified here. A retry child links to its parent failed edition; the parent is a referenced record, not reconstructed parent content. Queue acknowledgement is not an execution permit.

The host must authenticate and authorize the snapshot and private export. The component is not an authorization or receipt service. Consumed uncertainty stays unresolved after lease expiry. Worker identity and lease fields are record metadata, not persistent agent/live activity evidence. Submission and consumption times stay in inspectors; no raw audit timeline is invented. Completion/failure timestamps and actors are absent in the upstream record and explicitly disclosed as such.

The input is bounded to 64KiB, rejects unknown fields, inconsistent statuses, duplicate reference roles, foreign references and inconsistent retry identities. The graph/table/inspector share literal escaped content. No database, network, retry controls, dispatch or publication is added. Five synthetic snapshot/JSDOM groups cover status consistency, exact lineage and editions, unknown/foreign reference rejection, budgets and inert shared inspectors. They do not qualify real database/host/browser/accessibility or proof services. Final-head CI is recorded in the PR.

Processing is pinned to accepted source `6f99bc8aea2f7f7def6264c70d81bf0345315ba7`. The pin update also runs existing caption tests against that accepted source. Reference objects reject extra fields and conflicting reference roles are rejected rather than silently merged. This view supports one job at a time; it does not assert collection completeness or load root/parent history. Delivery stage is supplied by the trusted host and distinct from job execution status.
