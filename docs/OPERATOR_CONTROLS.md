# Private operator controls

The opt-in `./operator-client` and `./operator-controls` subpaths connect an authenticated host to the accepted Correspondence COE-004 operator API. The client is pinned to that accepted source commit. Mounting requires an explicitly supplied client/transport and matching HTTPS document origin. No transport, session, server or credentials are provisioned by this package. The existing static inbox remains a private read-only export with network disabled.

The mounted component supports opening existing conversations, creating/revising private drafts, marking read, archiving, refreshing and human takeover. It displays unverified replies as text. It has no send, publication, grants, autonomous enablement or resume control. The mounted list provides All Mail, Inbox, Archive, Drafts, Unread, Starred, Sent, Trash and Spam views, literal search, and Previous/Next navigation through 50-record pages. Navigation requires the same observed mailbox revision; concurrent changes leave the existing page visible and require explicit refresh/review. New conversation composition creates a private conversation followed by its private draft. Host authentication and per-command backend roles remain authoritative: client-side buttons do not grant permissions.

Requests use fixed same-origin operator paths, same-origin credentials, no-store and redirect rejection. The session CSRF token is held only in memory and is not rendered or persisted to browser storage. The server fixes scope/mailbox; the client never supplies actor, roles or tenant authority. Responses have byte/chunk/time bounds and error messages never expose raw transport/server diagnostics. The host must use an appropriate CSP with connect-src restricted to itself, secure session cookies and ordinary protected data access. This mounted network-enabled component must not be inserted into the offline export while retaining that export's no-network acceptance claim.

Each edit captures the viewed domain revision, draft version, unique command ID and input values. There is no automatic retry. An uncertain network/5xx/malformed response retains an immutable pending command, blocks new edits and preserves the current editor. Explicit Resolve pending edit replays the exact original envelope after obtaining a fresh CSRF token; it may commit the original private edit if the first attempt never reached the server. It is not a new edit or external-send retry. Revision conflicts require reload/review; unsaved text remains until the user explicitly reloads/selects. Disposing the mount prevents late reads from altering detached UI.

Takeover reports committed handoffs as unrecallable and does not promise message recall. Browser/API errors cannot enable sending. Reconciliation success is followed by an explicit current-state refresh. The host must keep provider execution disabled unless separately authorized.

Tests execute the accepted operator handler and real domain transitions through an injected in-memory repository, plus JSDOM interactions for edits, takeover, lost acknowledgement, text retention and exact replay. These are not fresh SQL tests, real browser/accessibility certification or live session/TLS deployment acceptance. Correspondence's separate accepted tests cover durable SQL behavior. Remaining work includes authenticated host integration, responsive/browser/assistive-technology acceptance and richer case views.

## Two-stage composition and recovery

The first submit captures recipient, subject, text and stable conversation/draft/command IDs. Fields and unrelated navigation lock after capture. A successful conversation creation advances only to the draft stage; it is not evidence that the draft was saved. Both stages normally run in order on that explicit submit. Unknown responses block further writes and retain the exact pending command. Reconciliation of an unknown first stage does not automatically start the second: the user explicitly selects Create conversation and draft again. Reconciliation of the draft stage displays the saved draft.

A definitive second-stage rejection leaves the conversation intact and labels the draft incomplete. Cancel composition never deletes that conversation or claims rollback. Inputs remain available to copy until explicit cancellation. State and pending input are held in memory only; the host must handle navigation/logout lifecycle and private recovery storage before claiming crash/reload recovery for unsaved browser input. No send intent is created.

## Folder and search navigation

The folder selector and Search/Enter action query the accepted same-origin operator API. Clear search retains the selected folder. Applying either filter resets the requested offset to zero; pagination retains the committed folder/query and observed page revision. These are local private workspace views/flags, not provider-folder synchronization. Search behavior (including excluding trash/spam from other views) is the existing Correspondence projection, not a new client-side interpretation. Queries can be sensitive; the host must protect/redact request logs and retain its no-store/session controls.

Filters commit only after a successful read. Failure restores the committed selector/query and retains the list and conversation editor. Changed revisions during Previous/Next leave the prior page intact and require explicit refresh. Unsaved draft text blocks folder/search changes and flag commands before issuing requests; save the private draft or explicitly Close conversation to discard local text. Normal explicit conversation selection/refresh retain their documented reload semantics. Mark read/unread and Star/Unstar toggle the viewed thread flags and refresh filtered membership after the private flag command. These controls use the viewed revision and cannot grant sending authority.

Pending edits and captured two-stage composition disable filter controls. Programmatic change events cannot issue filter reads during those states. Cancelling a partial composition retains the already-created conversation; it never claims rollback. Disposal prevents late reads from writing even to detached filter controls. Tests use the actual operator handler/domain projections through an injected in-memory repository and JSDOM, not real provider, SQL/network-session, browser or assistive-technology acceptance.
