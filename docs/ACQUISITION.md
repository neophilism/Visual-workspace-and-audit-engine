# Private acquisition coverage and recovery audit

The `./acquisition` projection connects an already-authorized `ScheduleSnapshot` from the pinned Discovery SDK to the existing dependency map, accessible record table, timeline and exact-record inspector. The host authenticates the viewer, filters/authorizes the whole input and supplies an evidence-backed delivery stage. Snapshot strings and hashes are not authentication, and the projection performs no database access, network requests, worker dispatch or mutation.

Coverage totals describe the entire approved collection, while item/attempt windows disclose exactly which history is displayed and the next offsets. A history page also includes the real item dependencies of its attempts. Captured items, acquisition count and unique byte editions remain distinct; none is an incident count or a factual verification. Unseen/failed items and consumed uncertainty remain visible. Consumed unresolved work is never relabeled as a safe failure or retry opportunity.

Every derived collection/item/attempt node carries the actual containing storage revision; an actual linked receipt retains its own exact reference revision. Receipt content and current permissions are not reread. Scope is checked even on receipts outside the selected history window, and inconsistent identities, completion states, missing references and digests are rejected. Raw lease tokens, user-agent/access-basis configuration and full source policies are excluded. Approved source URLs can still be sensitive; the host must authorize their display/export.

Only real recorded lease/start and completion timestamps appear in the timeline. The current scheduler snapshot does not retain consumption/recovery timestamps or completion actor, so this adapter explicitly reports those gaps. It does not reuse the lease owner as the completion actor or turn a lease deadline into a fabricated recovery event. No persistent agent identity or live position is inferred from an acquisition assignment.

At most 100 item selections and 200 attempts are rendered per window, plus required dependencies and receipt nodes. Overall collection coverage is calculated before windowing. This is a read-only bounded snapshot, not a live subscribed navigator. A host can request other windows from the same exact storage revision; it must re-review after a changed revision.

Tests exercise actual Discovery collection transitions, scope/history/window rejection and executed JSDOM graph/table inspector behavior with inert script-like identifiers. These establish neither fresh SQL/network acceptance nor real-browser/assistive-technology acceptance. Host session integration, deployed acquisition workers, fuller provenance/service lookups and browser qualification remain pending.

`docs/examples/private-acquisition.html` is a deterministic fictional example generated by `npm run example:acquisition`. It includes captured, failed, running, reconciliation-required and unseen work and can be inspected locally. It contains no real records or deployment configuration.
