# Private participant controls

`mountParticipantControls(root, client, offerId)` from `./participant-controls` mounts a single offer review into a private same-origin host. `client` is the accepted `ParticipantClient` from Consent PR8, pinned at `43c4d786be774ee61c03c8ec599c4ee3521046e9`. The component refuses a different document origin or a retained pending command for another offer. It neither loads nor writes automatically. A client can have only one mounted owner and a closed client cannot mount. Transfer exclusive client ownership to this component: the host must not call review/respond/withdraw/replay directly while mounted, because the client stores its latest internal viewed review. Create separate clients for separate authenticated views; do not share mutable client state between screens.

An explicit **Review current offer** fetches the authenticated snapshot. The screen shows the exact disclosure, review digest, offer/resource/evidence editions, subject, actions, purposes, audiences, permission window, response deadline and warnings as literal DOM text. Accepted offers retain the original historical capture binding and show the separately reviewed current consent/withdrawal edition. This screen does not authorize use or establish identity, reading, comprehension, consent capacity, rights ownership or release permission.

Acceptance has no default and requires the initially unchecked acknowledgement. Decline is a separate explicit action without requiring acknowledgement. Withdrawal is enabled only after reviewing the accepted offer's own unwithdrawn consent. Each action creates one command ID and delegates exact internal review/CSRF/actor/scope/current-server-mapping enforcement to the pinned client and accepted handler. The client captures immutable commands before POST. Busy/pending/closed guards cover both native disabled controls and direct event dispatch.

Unknown, invalid or rejected writes lock review and all new decisions. Only **Resolve exact pending request** explicitly replays the exact original body after a fresh session/CSRF; there is no automatic retry, polling, replacement ID, mode switch, invitation, manager, send or publication action. A returned accepted receipt remains historical, including when reconciliation follows a later withdrawal. After any acknowledged action, the user must explicitly review current state before another decision. Pending details are displayed as literal command metadata, with no CSRF or credentials.

Dispose the component on logout, identity/purpose/deployment-policy change or navigation; this removes listeners, closes the client and prevents late writes to mounted or detached controls. The client retains a detached pending getter for trusted host review even after disposal. A closed client cannot replay. Pending state and reviewed input are MEMORY ONLY: the host must retain unresolved intent and qualify private crash/reload recovery rather than recreate clients to bypass it. A read error clears the actionable view; it does not assert a mutation rolled back. Withdrawal cannot recall copies already obtained.

Host prerequisites: independently authenticated same-origin participant sessions, current subject mappings/roles/purpose/time, session/CSRF binding and logout lifecycle, secure cookies/TLS/CSP, protected offer navigation, rate/concurrency limits, accessible language and informed-consent review. An unchanged actor ID alone cannot detect every session/purpose change. DOM labels, status regions and literal-text tests are not browser or assistive-technology qualification. Existing offline audit consent views remain separate.
