# Private operations projections

The `./operations` subpath accepts typed storage snapshots from the pinned Resources and Packaging SDKs. The authenticated host must fetch an authorized, filtered current aggregate and explicitly supply its evidence-backed delivery stage. A business state such as `approved` or `settled` does not establish implementation, test or live acceptance. Scope checks and hash-chain consistency do not authenticate arbitrary caller JSON.

`projectBudget` shows the actual storage revision, integer spending/reservation/availability totals, separate reservation states and the cost timeline. Uncertain outcomes remain allocated and are visibly marked for reconciliation. Receipt references are checked for scope. Cost ledger chain corruption is rejected. The projection is read-only; it cannot reserve money, settle a charge or invoke a provider.

`projectReleases` retains every ordered manifest edition and links its exact artifact, source, rights, consent and editorial editions. Corrections remain visible alongside prior approvals. The same artifact bytes may appear with different package-specific decision editions; the graph retains both instead of rewriting artifact history. Conflicting hashes, gaps, duplicate editions, reference collisions and cross-scope bindings fail closed. Display-generated kinds `release-manifest` and `release-control` are reserved and cannot be reused by a binding in this projection.

Release events are bound to the exact containing storage aggregate. The original domain event does not carry a manifest revision, so the projection does not invent one or attach an old event to the latest manifest edition. Selecting a manifest shows its exact historical contents, hash, reason and containing storage revision. These are private audit records, not permissions to release them.

The existing renderer supplies the dependency graph, accessible record table, timeline and exact-record dialog. No forms, mutation buttons, remote links/assets, database access, live subscription or publication API are added. Ordinary private data-access controls must protect the generated HTML. Trusted operator IDs, purposes, reasons and receipts may be sensitive; the host decides which authorized records to export. A private metadata export is not redacted automatically for a public audience.

Tests use real upstream domain transitions and the compiled pinned SDKs. Projection tests cover uncertainty totals, historical corrections, distinct decision editions, scope/hash/history/reference rejection and delivery-stage separation. DOM tests execute the generated inspector and verify exact historical selection with inert injected script text. Native dialogs are stubbed in JSDOM; real browser, assistive technology, live storage/subscription and operational acceptance remain separate.
